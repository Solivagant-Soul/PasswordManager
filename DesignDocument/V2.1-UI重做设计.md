## 1. 背景与目标

V2 功能增强（T32–T47）交付后实机走查，暴露两类问题：**若干交互缺陷导致功能「不生效」**，以及**实现界面与设计稿在视觉与信息架构上差距明显**。

本轮目标：

1. 修掉走查中确认的 7 项交互缺陷，让已交付功能真正可用；
2. 以设计稿为准绳重做整体 UI——建立主题、公共组件与设置页的信息架构；
3. 收口「类型 vs 分类」的功能重叠。

**成功标准**：装机后逐条走查本轮验收清单（§8）全部通过，且四个 Tab 与全部子页的渲染与设计稿在结构、层级、色彩上对齐。

## 2. 已确认的产品决策

以下为 2026-09-25 与用户确认的收口结论，是本设计的输入前提。

| 编号 | 决策 | 理由 |
|---|---|---|
| D1 | **删除条目类型（FR-15），全部用分类** | 设计稿「新建条目」页只有分类一个字段；类型与分类职责重叠。数据库 `entries.type` 列保留不删（不写迁移），新建默认 `ACCOUNT`，不再有 UI 入口。**代价**：列表副标题不再按类型掩码，银行卡/证件会在列表中直接显示用户名——本期接受 |
| D2 | **设置主页保留：一期能做 + 已交付 + 导入/导出（置灰）** | 「账户与同步」删除（纯本地无账号体系）；「安全备份」删除（二期且与导入/导出重复） |
| D3 | **导入/导出本轮只做置灰占位** | 加密备份导出/导入属二期；本轮点按弹「即将推出」，不实现逻辑 |
| D4 | **生成器选项（长度/字符集/排除易混淆）提升为全局偏好** | 编辑页点「⚡生成」直接生成并填入，零弹窗；生成器页与编辑页读同一份 DataStore 偏好 |
| D5 | **详情页：TOTP 置灰保留，分享按钮删除** | TOTP 属二期；分享涉及明文外传，本轮不加 |
| D6 | **图标：M3 内置图标集 + 自绘 9 个矢量图** | 不引 `material-icons-extended`（本机网络对大 aar 下载不可达，CLAUDE.md 已记录） |
| D7 | **编辑页保留标签输入框** | 设计稿未画标签，但标签是 FR-5 已交付能力且列表副标题/筛选在用；删除会动数据模型，故折叠为次要位置保留 |

## 3. 缺陷修复清单

全部为已定位到具体代码行的根因修复，不含设计判断。

| # | 现象 | 根因 | 修复 |
|---|---|---|---|
| F1 | 自动锁定档位点了不刷新 | `VaultViewModel.autoLockDuration` 是普通 `var`，非 Compose 可观察状态（`VaultViewModel.kt:175`）；`AppNav` 把它当参数传递，但无状态变化触发重组 | 移入 `VaultUiState.autoLockDuration`，与 `defaultPasswordLength` 同款做法；`setAutoLockDuration` 写 `_state` |
| F2 | 设置页不能下滑、看不到分类 | `SettingsScreen` 用 `Column(Modifier.fillMaxSize())`，无滚动容器；分类管理写在最底部被挤出屏幕 | 顶层换 `LazyColumn` |
| F3 | 详情页收藏点了不渲染 | `toggleFavorite` 只改 Room；列表由 Flow 重发，但详情页数据源 `details`（`mutableStateMapOf`）无人重新加载 | 收藏切换成功后重新 `loadDetail(id)` |
| F4 | 复制密码无提示 | `copyPassword` 复制完即结束，未写提示 | 复用现有 `successMessage` 字段，经 Snackbar 展示「已复制，30 秒后自动清除」；不新增状态字段 |
| F5 | 生成器顶端有返回键；最长 64 位 | `GeneratorScreen` 顶部有 `TextButton("← 返回")`，但它是 Tab 根页无回退语义 | 移除返回键；`PasswordGenerator.LENGTH_MAX` 由 64 改为 32 |
| F6 | 安全中心须手动点检测 | `SecurityCenterScreen` 在 `report == null` 时只渲染「开始安全检测」按钮 | 进入 Tab 且 `report == null` 时自动 `startScan()`；`report != null` 时不重复扫描 |
| F7 | 密码列表页底部有「设置」按钮 | `EntryListScreen` 底部 `TextButton(onSettings)`，与底栏设置 Tab 重复 | 删除；`EntryListScreen.onSettings` 参数一并移除 |

**附带订正**：`CLAUDE.md` 记载的「列表非响应式（`search()` 用 `.first()`）」缺口**已不成立**——`EntryRepositoryImpl.search` 返回 `Flow` 且 `applyFilters()` 在 collect，列表实际是响应式的。同步订正 `CLAUDE.md` 与需求文档 §15 中「现为一次性取值+手动刷新」的过时描述。

## 4. 导航结构

维持「四个 Tab，每 Tab 一个独立回退栈」的既有决策（T44/T49），不引入 navigation-compose。`Screen` sealed interface 扩充设置子页：

```kotlin
sealed interface Screen {
    data object List : Screen
    data class Detail(val entryId: String) : Screen
    data class Edit(val entryId: String?) : Screen
    data object Generator : Screen
    data object Security : Screen
    data object Settings : Screen
    data object About : Screen

    // 设置子页（v2.1）
    data object SettingAutoLock : Screen
    data object SettingBiometric : Screen
    data object SettingDefaultLength : Screen
    data object SettingCategories : Screen
    data object SettingChangePassword : Screen
}
```

- 子页只压入 `AppTab.SETTINGS` 栈；`BackHandler(enabled = backStack.size > 1)` 逻辑不变，返回键逐级回退。
- 锁定时 `LaunchedEffect(state.locked)` 清空全部栈并重建各 Tab 根页，行为不变。
- `GeneratorScreen` 移除 `onBack` 回调（Tab 根页无返回语义）。

## 6. 各页面改造

### 6.1 密码列表（Tab 1）

对齐设计稿「密码页」：`PageHeader`（所有密码 / 共 N 个条目）+ 右上角锁图标 → 搜索框 → 分类 chips（全部/收藏/各分类）→ `EntryRow` 列表 → 右下角 FAB「＋」→ 底栏。删除底部「设置」`TextButton`（F7）。列表项本身已响应式，不改数据流。

### 6.2 条目详情

`TopBar`（返回 + 「条目详情」+ 右侧编辑/删除图标）→ 大头像 + 标题 + 分类徽章 → 信息卡片（用户名+复制 / 密码+显示隐藏+复制 / 网址+外链 / TOTP 置灰行 / 备注）→ 底部按钮区「编辑」「收藏」。

- TOTP 行置灰标注「即将支持」（D5）。
- 收藏按钮显示当前状态，点击即时翻转（F3）。
- 复制成功经 Snackbar 提示（F4）。

### 6.3 条目编辑

对齐设计稿「新建条目」：`TopBar`（返回 + 「新建条目」/「编辑条目」+ 右侧「保存」）→ 名称 → 用户名 → 密码（尾部内嵌「⚡生成」按钮）→ 网址 → 分类 chips（含「未分类」）→ 备注 → 标签（次要位置，D7）。

- **删除「类型」整组 chips**（D1）。
- **删除「收藏」复选框**——收藏入口收敛到详情页，编辑页不再重复。
- **「⚡生成」零弹窗**（D4）：调用 `PasswordGenerator.generate(全局偏好)` 直接填入密码框。删除 `GeneratorDialog` 文件与调用点。
- 标签输入框保留但移到备注之后，用 `bodySmall` 弱化。

### 6.4 生成器（Tab 2）

对齐设计稿「密码生成器」：结果常驻卡片（等宽字体）→ 强度条 + 评级 → 长度滑块（4–32）→ 四个字符集开关 → 排除易混淆开关 → 「重新生成」「复制密码」双按钮。

- **移除顶部返回键**（F5）。
- 全部选项读写全局偏好（DataStore），与编辑页共用（D4）。
- 页面级滚动容器（当前内容可能超屏）。

### 6.5 安全中心（Tab 3）

对齐设计稿「安全中心」：标题 + 「上次扫描：今天 09:12」→ 四张统计卡（总数/弱密码/重复使用/长期未更新）→「需要处理」列表（每行带「去修改」）→「安全建议」区。

- **进入 Tab 自动扫描**（F6）：`LaunchedEffect` 中当 `securityReport == null && !scanning` 时调 `startScan()`。
- 「去修改」跨 Tab 跳详情（现有行为保留）。

### 6.6 设置（Tab 4）

主页为 `SettingRow` 列表（§4.1）。各子页承载具体设置：自动锁定档位（chips）、生物识别开关（需验主密码 + 诊断入口）、默认密码长度（滑块或步进）、分类管理（增删改）、修改主密码（三输入框表单）、关于（现有 `AboutScreen` 不动）。

### 10.2 实施中实际发生的风险（2026-09-25 补记，按实况）

以下六条都是**实施过程中真实踩到**的，不在原计划的风险表里。原计划低估了
「按设计稿写代码」与「照 spec 抄」之间的差距。

| # | 风险 | 实际发生了什么 | 处置 |
|---|---|---|---|
| R1 | **spec 引用了 `material-icons-core` 里不存在的图标** | §5.2 初稿列出的 9 个名字——`ChevronRight` / `Visibility` / `VisibilityOff` / `ContentCopy` / `StarBorder` / `Key` / `Fingerprint` / `Security` / `SwapVert`——**全部不在该库里**。若照抄，T53 之后**每个 UI 任务都会编译失败**（约 5 个批次连锁返工）。 | 从 aar 内 `classes.jar` 解包，核实 `Icons.Default.*` 确切 **49 个**并改写 §5.2；自绘图标由 8 枚扩到 **13 枚**（`res/drawable/` 实测）。**教训：引用图标前先解包核实，不要凭记忆写。** |
| R2 | **M3 1.3 配色槽位静默回落** | BOM 2024.12.01 对应 material3 **1.3.1**。只赋 `primary`/`background`/`surface` 等「显眼」槽位时，`outline` / `outlineVariant` / `surfaceContainer*` / `surfaceTint` / `scrim` **未赋值会静默回落到 M3 基线紫**——而 `Card` / `OutlinedTextField` / `Dialog` / `NavigationBar` 恰恰取这些值。**编译零 error、lint 零 error，肉眼才看得出边框发紫。** | T54 Step 0 补齐全部槽位。**教训：换 M3 版本时，槽位清单是隐式契约，必须逐个对照补。** |
